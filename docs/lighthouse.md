# Lighthouse: локальный аудит

Проверка: 18 сентября 2026 года (Europe/Minsk). Lighthouse 13.4.1, Chrome 153, Windows, production-сборка Vite на `http://127.0.0.1:4173`.

**Порог ≥ 90 во всех категориях подтверждён для четырёх из пяти страниц в обоих режимах. Исключение — Performance мобильной страницы карты (83). Для всего приложения бонус пока закрыт не полностью.**

## Что изменено

- Фотографии блюд и сотрудников преобразованы в WebP подходящего размера: суммарно 4 546 787 → 103 602 байта. Состав изображений сохранён.
- Lora 600 подключена локально вместо блокирующего запроса Google Fonts; лицензия находится рядом со шрифтом.
- CSS Leaflet загружается только на странице карты.
- Карта начинает загружаться параллельно с данными Firestore; видимые тайлы получают высокий приоритет. Отключена анимация появления тайлов.
- Используются стандартные тайлы 256×256 того же стиля вместо Retina 512×512. На экранах высокой плотности карта менее детализирована; мобильный Best Practices — 96 из-за разрешения изображений.
- Добавлен корректный robots.txt; исправлены выявленные проблемы контраста и доступных названий кнопок.

Новые страницы и зависимости приложения не добавлялись. Временные Lighthouse, Playwright, Sharp и источник шрифта установлены вне проекта.

## Что ещё ограничивает результат

Мобильный Performance карты: 69 до изменений → 83 после, LCP 12,1 → 4,1 секунды. В итоговом отчёте остаются задержка обнаружения LCP-изображения, загрузка тайлов стороннего сервиса и стоимость JavaScript. Кэширование и формат тайлов контролирует провайдер. Для полного закрытия бонуса требуется дальнейшая оптимизация этой страницы и повторный аудит после деплоя.

Стандартный формат тайлов описан в [документации Stadia Maps](https://docs.stadiamaps.com/map-styles/alidade-smooth/).

## Условия и воспроизведение

Использованы стандартные профили Lighthouse: mobile — simulated throttling, 4× CPU slowdown, 412×823; desktop — штатный desktop preset. Перед каждой страницей запускался отдельный профиль Chrome. Аудиты не исключались, данные Firestore и тайлы карты не подменялись. Предупреждений Lighthouse в итоговых отчётах нет.

1. Настроить окружение по README, выполнить `npm run build`.
2. Запустить `npm run preview -- --host 127.0.0.1 --port 4173 --strictPort`.
3. Запустить Lighthouse для нужного адреса:

```bash
npx --yes lighthouse@13.4.1 http://127.0.0.1:4173/restaurants --chrome-flags="--headless" --only-categories=performance,accessibility,best-practices,seo --output=html --output-path=lighthouse-mobile.html
npx --yes lighthouse@13.4.1 http://127.0.0.1:4173/restaurants --preset=desktop --chrome-flags="--headless" --only-categories=performance,accessibility,best-practices,seo --output=html --output-path=lighthouse-desktop.html
```

Повторить для `/`, `/staff/tables`, `/staff/tables/table-3`, `/staff/employees`. Для сопоставимых результатов закрыть другие приложения с высокой нагрузкой и использовать чистый профиль браузера.

Полные исходные HTML- и JSON-отчёты текущей проверки сохранены локально в `node_modules/.cache/lighthouse/final/` (например, `mobile-restaurants.html`). Они исключены из Git вместе с node_modules; при необходимости их можно приложить к сдаче отдельно. После переустановки зависимостей отчёты могут исчезнуть.

Проверка интерфейса в Chrome после оптимизации: 375, 1020 и 1440 px; на страницах карты и сотрудников нет горизонтального переполнения всей страницы, сломанных изображений и ошибок JavaScript. Автоматический Accessibility 100 не заменяет полную ручную проверку доступности.

После деплоя необходимо повторить аудит публичного URL: сеть, сжатие, кеширование и доступность Stadia Maps могут изменить результат.
