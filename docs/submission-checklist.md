# Проверка задания стажировки

Extra с WebSocket исключён по решению автора проекта. Проверка не подразумевает новые экраны или переработку макета Figma.

## Обязательные требования

| Требование                          | Состояние                                                                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React + TypeScript + Vite           | Выполнено; TypeScript strict, сборка Vite                                                                                                                     |
| Без `any` в написанном вручную коде | Выполнено; ESLint запрещает явный `any` и проверяет небезопасные операции                                                                                     |
| TanStack Router, несколько страниц  | Выполнено; сохранены пять существующих маршрутов                                                                                                              |
| TanStack Query + Firebase Firestore | Выполнено; чтение через query, изменение через mutation, REST-only Firestore Lite                                                                             |
| Загрузка и изменение данных         | Реализованы чтение ресторанов/сотрудников/столов и изменение/завершение заказа                                                                                |
| Кэширование                         | Ключи заказов зависят от стола; после изменений обновляется/инвалидируется кэш                                                                                |
| Разделение логики и представления   | Логика заказа вынесена в hook, API и расчёты; routes содержат подключения feature-страниц                                                                     |
| Модульная структура                 | Features, общие утилиты, dev-данные; дубли коллекций удалены                                                                                                  |
| shadcn/ui / Tailwind                | Используются существующие компоненты и стили                                                                                                                  |
| Адаптивность                        | Исправлено переполнение существующих блоков; таблицы используют внутреннюю прокрутку. Мобильный вариант не сверен с Figma: ссылка на макет не предоставлялась |
| GitHub-репозиторий                  | Remote настроен; новые локальные изменения ещё нужно закоммитить и отправить                                                                                  |
| README, зависимости, запуск         | Описаны                                                                                                                                                       |
| Деплой и ссылка                     | **Не выполнено**: деплоя пока нет; конфигурация Vercel подготовлена                                                                                           |
| Устный опрос                        | Нужно подготовиться самостоятельно; результат пока не подтверждён                                                                                             |

В сгенерированном `routeTree.gen.ts` TanStack использует `any` и `@ts-nocheck`. Это код инструмента, исключённый из линтера; переписывать его вручную нельзя, изменения будут перегенерированы.

## Что осталось от исходного макета

Сохранены элементы-заглушки дополнительных разделов, профиля, уведомлений, корзины, статистики и управления сотрудниками. Они не являются готовыми функциями: часть показывает уведомление «coming soon», часть выделения пока не обрабатывается. При демонстрации не стоит заявлять их как реализованные.

У свободного/зарезервированного стола нет кнопки открытия заказа, и закрытые заказы нельзя снова открыть через интерфейс. Это исходный объём макета, а не добавленное требование задания. Для демонстрации изменений используйте уже занятый стол.

Данные смен A/B отображаются исходным интерфейсом как «On Shift» / «Idle»; реального расписания для определения текущей смены нет.

## Результаты локальной проверки

- `npm run check`: форматирование, ESLint, 32 теста и production-сборка прошли.
- Все пять маршрутов открываются в Chrome; ошибок JavaScript не обнаружено.
- Проверены ширины 320, 375, 768 и 1440 px: нет горизонтального переполнения страницы, широкие блоки прокручиваются внутри.
- Проверены поиск ресторанов и пустая выдача.
- Проверено сохранение черновика комментария при ошибке записи: запрос commit перехвачен и отклонён в браузере, живая база не изменялась.
- Временный Playwright после проверки удалён из зависимостей.

## Границы проверки

- Юнит-тесты проверяют валидацию, расчёты и логику операций с подменённым Firestore.
- Браузерная проверка читает существующие данные. Живые заказы для тестирования не изменялись.
- Опубликованные Firestore Security Rules, авторизация и серверное разграничение ролей не настраивались.
- Lighthouse: четыре страницы ≥ 90 во всех категориях на mobile и desktop; у карты mobile Performance 83. Подробности — [отчёт Lighthouse](lighthouse.md). Полная HTML/CSS-валидация не проводилась.
- Публичный деплой, его прямые ссылки и загрузку тайлов карты необходимо проверить после публикации.

## Для устного опроса

Нужно уметь объяснить:

1. Чем серверное состояние TanStack Query отличается от локального состояния React.
2. Зачем query key содержит ID стола; что такое `staleTime` и invalidation.
3. Чем query отличается от mutation и когда выполняется `onSuccess`.
4. Почему типизация не заменяет runtime-проверку данных Firestore.
5. Почему `unknown` безопаснее `any`.
6. Для чего заказу `revision`, а закрытию — транзакция.
7. Почему денежные суммы считаются в центах.
8. Как устроены file-based routes и почему не редактируют `routeTree.gen.ts`.
9. Что попадает в браузер из `VITE_*` и как настроить SPA rewrite.
10. Какие функции действительно реализованы, а какие оставлены элементами макета.
